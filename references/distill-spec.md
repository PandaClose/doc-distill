# 蒸馏规格（distill-spec）

> 移植自 book-to-skill 的核心理念：**Extract structure, not summaries.**
> 产物是工具箱，不是读书报告。

## 产出物是什么

一个手册型 skill，包含：

1. **SKILL.md**（≤400 行）——常驻入口：何时使用、章节地图、三节蒸馏成果
2. **references/full/**——原文分块（导出器已生成，不需要你动）

你要补全的是 SKILL.md 中的三节，并在必要时修订章节地图：

- **核心框架**：3~7 个命名框架/心智模型
- **高频模式与技巧**：可复用的模式、步骤化方法、代码惯用法
- **决策速查**：「遇到 X → 做 Y」规则表 + 反模式清单

## 提炼什么

- **命名框架**（mental models with clear application）：书中给了名字的思维工具。框架的名字就是它的接口——「5 Whys」「GROW 模型」「CAP 定理」必须原样保留，不能意译成描述句。每个框架输出：名字 + 何时用 + 一句话用法。
- **可行原则**：指导决策的规则。保留作者的限定条件（「在 X 情况下」不要丢）。
- **技巧**：step-by-step 的方法。有代码的给最小可运行示例（从原文摘录或按原文语义整合，不得引入原文没有的 API）。
- **反模式**：什么不要做、为什么。这类内容对 agent 行为的约束力最强，优先提炼。
- **作者口吻**（voice calibration）：作者的判断习惯、口头禅、经典比喻。蒸馏文本的措辞应贴近作者，让问答时有「这本书在说话」的感觉。

## 写作规则

1. **结构而非摘要**：不是按章节复述内容，而是把内容重组为「可被直接调用的知识单元」。检验标准：读完三节后，agent 能否不读原文就正确执行书里的方法？
2. **每条标注出处**：引用 IR 内容块 id（如 `[0012]`）或章节名。用户追问时 agent 才能回溯原文。
3. **层次匹配复杂度**：简单资料 → 简短三节；10+ 框架的复杂书 → 框架节按主题分组，允许内部小标题。
4. **保留口语与犹豫**：作者的「一般来说」「我见过最多的情况是」是信息，不是噪音。
5. **不虚构**：原文没有的例子、数据、结论一律不造。资料没覆盖的角度直接舍弃。
6. **语言**：跟随原文语言；原书中文就写中文，英文书写英文。

## 模板

```markdown
## 核心框架

### <框架名（原文原名）>
- **何时用**：…
- **用法**：…
- **出处**：[0012] 第 3 章

## 高频模式与技巧

### <模式名>
<步骤或代码示例>
出处：[0031]

## 决策速查

| 遇到 | 做 | 不要 | 出处 |
|---|---|---|---|
| … | … | … | [0042] |

### 反模式
- **<反模式名>**：<为什么错、原文怎么说> 出处：[0050]
```

## 质量自检（交付前逐条过）

- [ ] 三节占位全部补全，`validate --strict` 通过
- [ ] 所有出处 id 在 references/full/ 中真实存在
- [ ] 框架名与原文一致（抽查 2~3 个对照原文）
- [ ] 没有原文不存在的结论/数据
- [ ] 章节地图与 references/full/ 文件一一对应
- [ ] SKILL.md ≤ 400 行
